Resource usage and capacity

Firecrawl's 1,000-URL dataset, scored like scrape-evals, on AWS Graviton machines. Each engine runs alone with the whole machine to itself. Concurrency rises until success drops, latency triples, or the engine runs out of memory.

In short

    Memory

    Average container memory over a 90-second run at each concurrency. Engines finish different numbers of pages in that time, so read it alongside throughput.

    CPU

    Average cores in use over the same runs; the dashed line is the machine's vCPUs

    Throughput

    Pages per second across all 1,000 URLs; hollow points failed the level

    Median latency

    Time from request to Markdown at each capacity level

    Success rate

    Share of URLs returned with a 2xx or 3xx status, some text, and no block page. It does not check the text is the right text.

    Content match (F1)

    Average word overlap with each URL's reference text, from 0 to 1, over all 1,000 URLs; a page with no text scores 0. Higher means the Markdown holds more of the right content.

    All machines

    Highest concurrency each engine sustained, and its numbers at that level

    How the levels are judged

    Each capacity level runs all 1,000 URLs once in a fresh container. A level fails if the engine crashes or runs out of memory, if its success rate falls more than 10 points below its best level so far, or if its median latency is more than 3× its latency at 8 concurrent pages. Firecrawl also runs 1, 2 and 4 because it can't reach 8 on the small machine; its latency is still compared with its level-8 run. The ramp also stops once throughput falls below 80% of the best level; that level still counts as sustained.

    Every point is a single run against live websites, so expect a few points of noise between runs. Memory and CPU come from separate 90-second runs at each fixed concurrency.

    Firecrawl runs in scrape-only mode (API and browser service, without the unused queue workers). Every engine is scored with the site's real HTTP status. Huntsman's robots.txt check, which is on by default, was turned off to match the other engines. Caching was turned off for Huntsman (maxAge: 0) and Crawl4AI (bypass); Firecrawl and Spider ran with their defaults, and no URL is requested twice in one container.

    Raw results for every machine and engine are in matrix/. To reproduce from the engine directory:

    go run ./benchmark/cmd/bench provision
go run ./benchmark/cmd/bench run --machine all --engine all --firecrawl-scrape-only
go run ./benchmark/cmd/bench report --inject benchmark/results/index.html
go run ./benchmark/cmd/bench destroy
